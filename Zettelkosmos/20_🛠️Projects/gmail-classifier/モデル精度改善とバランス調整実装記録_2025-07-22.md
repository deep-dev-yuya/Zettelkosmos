# 📊 Gmail分類モデル精度改善とバランス調整実装記録

本ドキュメントは、n8n実運用テストで発見された「支払いラベル偏重問題」と「時刻表示問題」を解決し、実運用データを活用してモデル精度を向上させた実装記録です。

---

## 🎯 実装概要

### 🚨 発見された問題点
1. **支払いラベル偏重問題**: 支払い関係が30.0%で最も高い分類率を示し、他カテゴリが適切に分類されない
2. **時刻表示問題**: Gmail APIの実際の受信時刻が使用されず、処理時刻のみが記録される
3. **学習データ不足**: 実運用データが十分に学習に活用されていない

### 🎯 解決アプローチ
- 実運用ログデータ（CSV）の分析と品質確認
- 支払いラベル偏重の根本原因特定と修正
- バランス調整された新しい機械学習モデルの開発
- 時刻処理システムの改善案策定

## 🔧 根本原因分析

### 1. 支払いラベル偏重の原因

#### **PayPay特化特徴量エンジニアリングの過剰適用**

**問題コード** (`app/classifier.py:22-130`, `models/train_model_paypay.py:17-125`):
```python
def create_paypay_specialized_features(text: str) -> str:

    paypay_variants = ['PayPay', 'paypay', 'ペイペイ', 'ペイ', 'PAYPAY']
```

```python
def create_balanced_features(text: str) -> str:

    payment_count = sum(1 for keyword in payment_keywords if keyword in text_lower)
```
